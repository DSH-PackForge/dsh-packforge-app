# 发布 / 打包指南

一个引擎、三个分发产物，按需各自出包，互不捆绑：

| 产物 | 目标 | 命令 | 输出 |
|---|---|---|---|
| 5 个 npm 包 | npm registry | `pnpm -r ... publish` | registry 上可 `pnpm add` |
| Electron 桌面端 | Windows 用户 | `pnpm --filter gui dist` | `packages/gui/dist/*.exe` |
| DSH 客户端插件 | DSH 内加载 | `pnpm --filter @dsh-packforge/plugin bundle` | `lib/client.js` |

> 沙箱内受「跳过构建脚本 + 全局写限制」影响：`pnpm pack`/`bundle` 已实测通过；
> `electron-builder` 出安装包、`pnpm link --global` 需在**本机 + 图形/网络环境**运行。
> 先执行一次 `pnpm approve-builds`，允许 `esbuild`、`electron`、`electron-builder` 的构建脚本。

## 1. npm 发布（5 包，依赖序）

```bash
cd dsh-packforge-app
pnpm install

# 插件发布前先出浏览器 bundle（lib/client.js）
pnpm --filter @dsh-packforge/plugin bundle

# 依赖序发布（workspace:* 会被 pnpm 自动转成 0.1.0）
pnpm -r --filter @dsh-packforge/core publish --access public
pnpm -r --filter @dsh-packforge/host-node publish --access public
pnpm -r --filter @dsh-packforge/host-dsh-plugin publish --access public
pnpm -r --filter @dsh-packforge/plugin publish --access public
pnpm -r --filter @dsh-packforge/cli publish --access public
```

验证（发布前本地打 tarball 检查，已实测 workspace:* → 0.1.0、files 不含 test/）：

```bash
pnpm --filter @dsh-packforge/cli pack   # 检查 tarball 内 package.json 的 dependencies
```

## 2. CLI 装成全局 `dspack`

```bash
cd packages/cli && pnpm link --global   # 之后任意目录可直接敲：
dspack --help
dspack list
dspack pack web --display-name "网页开发助手" --out ./dist
dspack install ./dist/web-1.0.0.dspack
dspack market <index.json>
```

> 若想发单文件 `.exe`（免 Node 环境），因本项目是纯 ESM，`vercel/pkg` 不友好，
> 建议用 Node SEA 或 esbuild bundle + 运行时壳；当前优先走 npm 分发。

## 3. Electron 桌面端打包（Windows）

```bash
pnpm approve-builds          # 允许 electron 下载二进制
pnpm --filter gui dist        # = electron-builder --win
# 产物在 packages/gui/dist/：DSH PackForge Setup x.y.z.exe（NSIS 安装版）+ portable.exe
```

配置在 `packages/gui/package.json` 的 `build` 字段（appId `dev.dsh-packforge.app`、
`files` 含 electron/renderer/src、win 目标 nsis+portable）。入口 `electron/main.mjs`、
preload `preload.cjs`、渲染资源 `renderer/`+`src/format.js` 均已确认存在。

> pnpm 隔离链接（symlink）下若 electron-builder 打包 workspace 依赖异常，
> 回退：加 `.npmrc` `node-linker=hoisted` 重装后再 `dist`。

## 4. DSH 客户端插件 bundle（M4）

DSH 客户端插件契约（已从 0.1.0-rc.8 源码确证）：

```jsonc
// package.json 内
{
  "dsh": { "client": { "platform": "web", "inject": ["@deepseek-ai/dsh-client-runtime"] } },
  "exports": { "./client": "./lib/client.js" }
}
```

- `exports["./client"]` = 浏览器 bundle；执行时注册 `window.__ModuleLoader__.load({id, factory})`。
- 本插件 bundle 由 esbuild 从 `src/client.js` 产出：单 IIFE、内联 core+host-dsh-plugin+fflate、**无 node: 内建**（已测试）。
- 产出：`pnpm --filter @dsh-packforge/plugin bundle` → `lib/client.js`（已实测 31.5KB）。
- 已加的 `dsh.client.inject` 为最小集，实机加载后再按需补。

> 插件仅靠 `ctx.fs`（无二进制写/mkdir/rm/move）时只能「就地查看 .dspack 字节流」；
> 完整导出/导入走 `ctx.shell` 委派 `dspack` CLI（CLI 需随插件一起入 host PATH 或打进插件）。
